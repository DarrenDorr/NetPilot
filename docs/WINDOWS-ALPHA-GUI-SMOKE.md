# NetPilot Windows Alpha — проверка первого пользовательского окна

**Назначение:** небольшой ручной GUI smoke на Windows 10/11 x64 для установленного **непривилегированного** NetPilot с закреплённым ByeDPI 0.17.3. Это отдельная проверка от GitHub-hosted R42.12.4 и не разрешает публикацию релиза.

## Что автоматизировано

- Windows CI компилирует Avalonia XAML приложения `NetPilot.App.Windows` и проводит Windows IPC/security тесты.
- `NetPilotAlphaDashboardViewModelTests` проверяет, что кнопка отображает состояние только после фактического ответа runtime, меню переключает ширину без удаления команд, а закрытие ViewModel вызывает освобождение DashboardService ровно один раз.
- Успех этих тестов **не доказывает**, что реальное окно отображается корректно на физическом мониторе.

## Как получить и проверить актуальный установщик

Это **только проверочный пакет для Windows Alpha**, а не опубликованный релиз ByeDPI.

1. Откройте [R42.12.4 GitHub Actions](https://github.com/DarrenDorr/NetPilot/actions/workflows/r42-12-4-no-admin-byedpi-validation.yml), выберите **Run workflow → main → Run workflow**. Требуется завершение **SUCCESS** на ожидаемом коммите `main`.
2. В странице успешного запуска откройте раздел **Artifacts** и скачайте `netpilot-r42-12-4-no-admin-pc-validation-pack`. Пакет доступен **в течение одного дня**. При FAIL установочный пакет теперь **не** загружается в Artifacts; диагностический отчёт остаётся доступным отдельно.
3. Распакуйте ZIP полностью в обычный локальный каталог (не запускайте EXE непосредственно из ZIP). Проверьте, что там присутствуют `package-manifest.json`, `NetPilot-UserMode-Setup-…-x64.exe`, `NetPilot-ByeDPI-NoAdmin-Validation.exe`, `verify-physical-pack.ps1` и эта инструкция.
4. Откройте PowerShell **без запуска от администратора** в каталоге распакованного пакета и выполните `powershell.exe -NoProfile -File .\verify-physical-pack.ps1`. Скрипт только читает файлы и контрольные суммы, ничего не устанавливает и не запускает. Требуются `R42_12_4_PACK_CHECK=PASS` и `R42_12_4_MANIFEST_BOUNDARY=PASS_BLOCK`. Сравните выведенный `NETPILOT_COMMIT` с коммитом запуска, а `HOSTED_RUN_ID` — с номером запуска GitHub Actions.
5. **Если проверка не прошла или Windows запрещает выполнение скрипта политикой безопасности — не обходите её.** Можно вручную сравнить SHA-256 установщика с `installer.sha256` в манифесте командой `Get-FileHash -Algorithm SHA256 .\NetPilot-UserMode-Setup-…-x64.exe`; при сомнениях остановите тест.
6. Запустите установщик только после проверки целостности, **в обычном пользовательском контексте и без UAC**. После установки, не повышая права, повторите `powershell.exe -NoProfile -File .\verify-physical-pack.ps1 -CheckInstalled`. Требуется `INSTALLED_GUI_SHA256=PASS`. Если Windows предупредит о небезопасном или неподписанном приложении, не отключайте защиту ради теста — сообщите о предупреждении.

Проверка установщика и хэша приложения **не гарантирует** правильный внешний вид или работу ByeDPI. Только после этого выполняйте шаги таблицы ниже. Не публикуйте файл установленного пакета или приватные диагностические сведения в открытых issue.

## Ручной GUI smoke на обычном пользователе Windows

Используйте строго проверенный **user-mode installer** и неизменённый кандидат ByeDPI. Не запускать от администратора, не соглашаться на UAC, не отключать Defender, не устанавливать дополнительные драйверы.

| Шаг | Ожидаемый результат | Статус |
|---|---|---|
| Запуск NetPilot из меню Пуск | Открывается тёмное окно без UAC или ошибки запуска | Не проверено |
| Главное окно 820×640 и 1100×790 | Кнопка, сервисы и события доступны без горизонтальной прокрутки | Не проверено |
| Свернуть/раскрыть меню | Левая панель меняет ширину; функции сохраняются | Не проверено |
| Запуск ByeDPI центральной кнопкой | Движок стартует под текущим пользователем; после подтверждения отображается «Остановить ByeDPI» | Не проверено |
| Проверить сервисы | Проверяются только сервисы из утверждённого каталога; маршрут direct и SOCKS5 отображается раздельно | Не проверено |
| Подобрать стратегию | Изменения происходят только по проверенному результату; ошибки не включают привилегированные режимы | Не проверено |
| Режим эксперта | Техническая информация отображается/скрывается без изменения сетевого состояния | Не проверено |
| Остановить ByeDPI | Процесс прекращается; статус подтверждает остановку | Не проверено |
| Закрыть окно при запущенном ByeDPI | Не остаётся дочернего `ciadpi.exe`; Job Object закрыт | Не проверено |
| Повторный запуск, ошибка пакета | Нет ложного «запущен», ошибка сообщается без путей/секретов | Не проверено |
| Удаление NetPilot | Удаление от обычного пользователя без повышения прав, без изменений системного прокси и WinDivert | Не проверено |

**Сохранять для проверки:** версия Windows, архитектура, SHA-256 проверенного кандидата, отметки PASS/FAIL по таблице и обезличенный локальный support bundle при сбое. Не публикуйте приватные логи, полный путь профиля пользователя или сетевые назначения.

## R44: разделить запуск прокси, HTTPS через SOCKS5 и работу приложения

После проверки установки пользователь выполняет тест **без администратора**, без изменения системного прокси/реестра/Firewall/DNS. Прошедший hosted CI не заменяет этот ручной тест.

1. Запустить ByeDPI центральной кнопкой. В режиме эксперта убедиться в состоянии «запущен» и увидеть **фактический** адрес `127.0.0.1:<порт>`. Перезапуск движка может изменить порт. **Критерий A**: процесс подтверждён, локальный listener зарегистрирован; это ещё не проверка внешней сети.
2. Нажать «Проверить через ByeDPI». Проверка должна относиться только к опубликованным ресурсам каталога; её результат **не равен** проверке приложения. Отдельно выполнить «Прямое подключение» и убедиться, что подписи маршрутов не смешаны. **Критерий B**: для конкретного ресурса HTTPS-запрос через SOCKS5 завершился с `Healthy`. Другие ресурсы могут иметь иной результат.
3. При необходимости, в **обычном PowerShell без администратора**, использовать встроенный `curl.exe` для независимой проверки только общедоступного тестового HTTPS-адреса. Сначала вручную заменить `PORT` на цифры подтверждённого порта из панели NetPilot (не копировать `<порт>` буквально):

   ```powershell
   curl.exe --noproxy "" --proxy "socks5h://127.0.0.1:PORT" --max-time 10 --max-redirs 0 --output NUL --write-out "HTTP %{http_code}`n" "https://example.com/"
   ```

   При несовместимости установленной версии curl с отдельной опцией завершить проверку, **не обходя** политику безопасности; можно использовать встроенную проверку NetPilot. Запрос не должен включать авторизацию, персональные URL или токены. **Критерий C1**: внешний клиент явно использовал этот SOCKS5 и получил ожидаемый HTTPS-ответ. Сам факт возврата HTTP-статуса, в том числе ошибки, не означает успеха.
4. Только для приложения, **явно поддерживающего настройку SOCKS5**, вручную установить host `127.0.0.1` и подтверждённый порт. При наличии отдельной настройки DNS через SOCKS использовать её по политике самого приложения. Для приложений, которые не поддерживают SOCKS5, отметить «не поддерживается», **не включать** прозрачный или системный перехват трафика. Проверить нужную функцию приложения и после этого отключить прокси в его собственных настройках. **Критерий C2**: реальная функция приложения работает по подтверждённому маршруту; отдельный успешный HTTPS-запрос сам по себе недостаточен.
5. Остановить ByeDPI и проверить, что локальный адрес исчез из интерфейса, порт закрыт, `ciadpi.exe` не остался и системные настройки не изменились. При изменении системного прокси/WinDivert или появлении UAC тест провален.

**Матрица доказательств:** A (движок запущен) ≠ B (проверка каталога) ≠ C1 (независимый SOCKS5-клиент) ≠ C2 (целевое приложение). Нельзя заменять C2 на B или объявлять поддержку UDP/QUIC/голоса/игровых протоколов на основании HTTPS. Зафиксировать по каждому шагу PASS/FAIL/NOT TESTED и код диагностики без URL, секретов, полного пути профиля или других личных данных.

## Ограничения текущего интерфейса

- Блок «Последнее событие» показывает **реальное локальное действие** из ViewModel, а не притворяется подключённой новостной лентой.
- Карточки отображают только сервисы проверенного каталога. Telegram и любые другие сервисы без проверенного endpoint не отображаются как проверяемые и не получают выдуманный статус.
- Глянцевые иконки и полноценный источник новостей относятся к дальнейшему UI Kit; они не должны задерживать безопасный работающий ByeDPI-only alpha.

Результаты фиксируются в [Issue #106](https://github.com/DarrenDorr/NetPilot/issues/106). До выполнения обязательных hosted, physical-PC и GUI проверок сохраняются `PRODUCTION_ADMISSION=BLOCK` и неопубликованный Draft `byedpi-v0.17.3`.
