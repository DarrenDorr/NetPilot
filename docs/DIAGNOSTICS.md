# Диагностика NetPilot

## Назначение

NetPilot хранит локальные диагностические журналы, чтобы при сбое можно было быстро определить этап ошибки без передачи содержимого пользовательского трафика или IPC-сообщений.

Журналы не отправляются автоматически в GitHub, OpenAI или другие внешние сервисы.

## Где находятся журналы

Пользовательский журнал GUI:

`%LocalAppData%\NetPilot\Logs`

Журнал Windows-службы:

`%ProgramData%\NetPilot\Logs`

Формат журналов — JSONL: одна структурированная диагностическая запись на строку.

Журналы автоматически ротируются. Срок хранения — до 7 дней, общий лимит каталога — 20 МБ, один файл — до 5 МБ.

## CorrelationId

Каждый IPC-запрос GUI к `NetPilot.Service` использует существующий `RequestId` как `CorrelationId`.

По этому идентификатору можно связать:

1. действие GUI;
2. запрос к Windows-службе;
3. результат службы;
4. диагностический код ошибки.

## Диагностические коды

Примеры:

- `NP-APP-START-001` — запуск GUI;
- `NP-APP-CRASH-001` — необработанное исключение GUI;
- `NP-IPC-REQ-001` — начало IPC-запроса;
- `NP-IPC-OK-001` — успешный ответ службы;
- `NP-IPC-FAIL-001` — служба вернула контролируемый отказ;
- `NP-IPC-ERR-001` — IPC-запрос завершился исключением;
- `NP-SVC-START-001` — запуск Windows-службы;
- `NP-SVC-CRASH-001` — аварийное завершение Windows-службы;
- `NP-DIAG-MANUAL-001` — ручная сборка support bundle.

## Как собрать пакет для разработчика

Закройте обычное окно NetPilot и выполните:

```text
"C:\Program Files\NetPilot\App\NetPilot.exe" --collect-diagnostics
```

Пакет будет создан в:

`%LocalAppData%\NetPilot\Support`

Имя файла имеет вид:

`NetPilot-Diagnostics-YYYYMMDD-HHMMSS-UTC.zip`

Файл `latest-bundle.txt` в этом же каталоге содержит путь к последнему созданному пакету.

При необработанном падении GUI NetPilot также пытается создать такой пакет автоматически.

## Что находится внутри ZIP

- `diagnostics.json` — версия приложения, последний безопасный диагностический контекст и `CorrelationId`;
- `environment.txt` — версия Windows/.NET и архитектура без имени пользователя и компьютера;
- `logs/app/*.jsonl` — пользовательские диагностические записи;
- `logs/service/*.jsonl` — журналы службы, если они доступны для чтения;
- `checksums.txt` — SHA-256 файлов пакета;
- `privacy.txt` — границы собираемых данных.

## Что намеренно не собирается

NetPilot не создаёт дамп переменных окружения и не должен записывать в диагностический пакет:

- пароли;
- cookies;
- API keys;
- authorization tokens;
- содержимое IPC-сообщений;
- содержимое браузерных профилей;
- пользовательский сетевой трафик.

Значения с типичными ключами `token`, `password`, `secret`, `authorization`, `cookie`, `api_key` дополнительно редактируются перед записью в журнал.

Имя локального пользователя, имя компьютера и путь профиля заменяются нейтральными маркерами.

Перед передачей ZIP третьему лицу пользователь всё равно должен иметь возможность просмотреть его содержимое.

## Для разработчика

При разборе проблемы в первую очередь сопоставляйте записи по `CorrelationId`, затем проверяйте `EventCode`, `ResultCode`, тип исключения и HResult. Полный текст IPC-запроса специально отсутствует.
