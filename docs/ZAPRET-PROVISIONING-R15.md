# Zapret Provisioning R15

## Цель

R15 подключает к пользовательскому интерфейсу уже проверенный в R6–R10 механизм установки и обновления Zapret.

Установка или обновление выполняется **только после явного нажатия пользователя**. Запуск NetPilot сам по себе не скачивает и не устанавливает сетевой движок.

## Главная граница безопасности

GUI не передаёт службе:

- URL;
- имя репозитория;
- путь к ZIP;
- путь staging;
- SHA-256;
- имя исполняемого файла;
- аргументы запуска;
- shell-команду.

IPC-команда называется `ZapretInstallOrUpdateOfficialLatest` и не содержит пользовательского payload.

Служба сама использует production-реализацию `GithubZapretReleaseClient`, которая жёстко привязана к официальному репозиторию:

```text
https://github.com/Flowseal/zapret-discord-youtube
```

## IPC v3

R15 повышает версию локального IPC до `v3` и использует отдельное имя Windows Named Pipe:

```text
NetPilot.Service.v3
```

Добавлены только две доменные команды:

1. `ZapretGetInstallationStatus` — чтение подтверждённого состояния установки;
2. `ZapretInstallOrUpdateOfficialLatest` — установка либо обновление последнего официального релиза.

Обе команды запрещают `StrategyId` и любые дополнительные JSON-поля.

Обычные IPC-команды сохраняют тайм-аут 5 секунд. Только provisioning получает ограниченный extended timeout 90 секунд, потому что включает HTTPS-загрузку, SHA-256, распаковку и файловую транзакцию.

## Как определяется установленный движок

Наличие произвольного каталога `current` недостаточно.

`ZapretInstallationInspector` требует одновременно:

1. отсутствие reparse point;
2. ожидаемую структуру официального пакета;
3. наличие `bin/winws.exe`;
4. набор `general*.bat`;
5. каталог `lists`;
6. корректный `.netpilot-engine.json`;
7. ожидаемый upstream ID `flowseal-zapret`;
8. корректную числовую версию.

Каталог, подложенный вручную без manifest NetPilot, не считается доверенной установкой.

## Установка

Если подтверждённого `current` нет, служба требует способность `EngineInstall`.

Далее применяется существующий pipeline:

```text
официальная release metadata
        ↓
проверка immutable release / asset
        ↓
загрузка только официального ZIP
        ↓
повторная проверка размера и SHA-256
        ↓
безопасная распаковка в .staging
        ↓
проверка структуры и reparse points
        ↓
транзакционная установка current
        ↓
manifest NetPilot
```

## Обновление

Если `current` уже подтверждён, служба требует способность `UpdateApply`.

Downgrade запрещён. Та же версия возвращает успешный статус `AlreadyLatest` без замены файлов.

Если Zapret был запущен, R10 сохраняет точный `StrategyId`, останавливает движок только после полной предварительной проверки пакета, применяет обновление и пытается восстановить **только ту же стратегию**.

Если прежняя стратегия исчезла или несовместима, другая стратегия автоматически не подставляется.

## Изоляция Windows-пользователей

Перед provisioning служба получает SID клиента из проверенного Windows access token.

Если Zapret сейчас работает и принадлежит другому SID, операция отклоняется с `EngineOwnedByAnotherUser` **до остановки движка**.

Если движок остановлен, R15 пока разрешает provisioning любому локальному интерактивному пользователю, который успешно прошёл Named Pipe authentication. Это не даёт доступа к данным другого пользователя, но является отдельным multi-user control policy. Перед публичным релизом будет проведена финальная сверка и при необходимости установщик закрепит постоянного владельца установки.

## GUI

На главном экране отображается:

- `Zapret ещё не установлен`;
- либо `Zapret установлен · версия X`.

Кнопка меняет подпись:

- `Установить Zapret`;
- `Обновить Zapret`.

Интерфейс явно сообщает, что источник фиксирован на официальном Flowseal и не может быть заменён через GUI.

## Что R15 не делает

R15 не:

- устанавливает Zapret скрыто;
- принимает произвольные источники;
- запускает произвольные процессы;
- автоматически выбирает другую стратегию после обновления;
- устанавливает Telegram engine;
- запускает стратегию автоматически после первой установки;
- выполняет provisioning в фоне без действия пользователя.

Первый безопасный запуск стратегии после свежей установки — отдельный следующий этап.
