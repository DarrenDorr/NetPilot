# Аудит безопасности NetPilot — 28.10.2026

## Область проверки

Проверен текущий код NetPilot после Security Foundation R1: приложение, Core, IPC, Windows-служба, Windows-платформенный слой, безопасность, резервное копирование, updater, абстракции движков, тесты, GitHub Actions, Dependabot, `.gitignore`, центральный список NuGet-зависимостей и глобальные параметры сборки.

Дополнительно выполнен целевой поиск по репозиторию на признаки:

- OpenAI / ChatGPT;
- API-ключей, токенов и паролей;
- HTTP-клиентов и сетевой отправки данных;
- чтения переменных окружения;
- запуска внешних процессов и shell;
- доступа к Windows Registry;
- произвольного чтения файлов;
- скрытых средств доступа к учётным данным.

Проверка относится только к текущему состоянию исходного кода. Ни ручной аудит, ни статический анализ не являются математической гарантией отсутствия всех возможных уязвимостей. Аудит повторяется перед релизами и после добавления сетевых движков, updater, импорта, backup, health-check либо новых привилегированных операций.

## Итог текущего этапа

На момент проверки не обнаружено исполняемого кода, который способен:

- входить в ChatGPT или OpenAI;
- получать cookie или сессионные токены ChatGPT/OpenAI;
- читать API-ключ OpenAI или `OPENAI_API_KEY`;
- обращаться к OpenAI API;
- читать браузерные профили или сохранённые пароли;
- читать Windows Credential Manager;
- отправлять пользовательские данные во внешнюю сеть;
- запускать произвольные shell-команды;
- читать произвольные пользовательские файлы;
- читать Windows Registry.

В центральном списке зависимостей отсутствуют OpenAI SDK и иные пакеты интеграции с ChatGPT/OpenAI. Текущий updater содержит только статические сведения о двух официальных Flowseal-репозиториях и ещё не выполняет сетевые загрузки. Backup-модуль пока содержит только модель манифеста и не читает/не записывает пользовательские файлы.

## Найденные проблемы и выполненное усиление

### 1. Политика привилегированных операций была default-allow

**Риск:** потенциально высокий для будущих версий, в R1 неэксплуатируемый из-за отсутствия реальных обработчиков.

`OperationPolicy` считал все значения `PrivilegedOperation` разрешёнными. При будущем добавлении обработчика новая операция могла бы стать разрешённой по умолчанию.

**Исправлено:** политика переведена на `default deny`. Сейчас запрещены все привилегированные операции. Каждая будущая операция включается отдельно после реализации авторизации, валидации и тестов.

### 2. Локальный клиент мог бесконечно удерживать IPC

**Риск:** средний, локальный отказ в обслуживании.

После подключения к Named Pipe служба ожидала запрос без собственного лимита времени.

**Исправлено:** введён общий IPC request timeout на стороне службы и клиента.

### 3. IPC JSON допускал числовые enum

**Риск:** низкий/защитное усиление.

Стандартный `JsonStringEnumConverter` по умолчанию разрешает числовые значения перечислений.

**Исправлено:** числовые enum запрещены, глубина JSON ограничена, неизвестные поля по-прежнему отклоняются. Добавлены отрицательные тесты.

### 4. `TrustedUpstream` можно было создать с произвольным URI

**Риск:** потенциальный supply-chain риск для будущего updater.

**Исправлено:** конструктор `TrustedUpstream` закрыт внутри updater-модуля и проверяет абсолютный HTTPS-адрес `github.com` без credentials, query и fragment. Добавлены тесты точных доверенных репозиториев.

### 5. GitHub Actions использовали плавающие major-теги

**Риск:** supply-chain/reproducibility.

**Исправлено:** `actions/checkout`, `actions/setup-dotnet` и `github/codeql-action` закреплены по конкретным commit SHA. Для checkout отключено сохранение GitHub credentials (`persist-credentials: false`). Runner закреплён на `ubuntu-24.04`.

### 6. NuGet vulnerability warnings не были блокирующими

**Риск:** зависимость с известной уязвимостью могла оставить только warning.

**Исправлено:** `NU1901`–`NU1904` переведены в ошибки сборки. `NuGetAudit` и `NuGetAuditMode=all` остаются включены.

### 7. Avalonia Trace включался и в Release

**Риск:** пока низкий, но в будущем подробная UI-диагностика могла случайно содержать пользовательские значения.

**Исправлено:** `LogToTrace()` оставлен только для Debug-сборок.

### 8. Список игнорируемых секретов был неполным

**Исправлено:** `.gitignore` дополнен форматами `p12`, `jks`, `keystore`, каталогом `.secrets` и типичными файлами credentials/secrets.

### 9. Отсутствовал автоматический запрет скрытой OpenAI/ChatGPT-интеграции

**Исправлено:** добавлен `scripts/security-policy-check.sh`, который выполняется CI и блокирует появление в исполняемом коде OpenAI/ChatGPT endpoints/`OPENAI_API_KEY`, а также опасные shell-пути (`cmd.exe`, PowerShell, `bash -c`, `UseShellExecute=true`, строковый `ProcessStartInfo.Arguments`).

### 10. SDK не был закреплён feature-band

**Исправлено:** `global.json` фиксирует .NET SDK `10.0.403` с `rollForward=latestPatch` и запретом prerelease, сохраняя возможность получать patch-обновления безопасности.

## Открытые блокирующие требования

Следующие пункты не являются текущими путями к чужим данным, потому что соответствующий функционал ещё не включён. Они являются обязательными security-gates перед его появлением.

### 1. Межпользовательская изоляция и двусторонняя аутентификация IPC

Текущий ACL Named Pipe разрешает локальных `Authenticated Users`, а R1 проверяет наличие локально идентифицируемого пользователя. Это допустимо только пока служба не выполняет реальные операции и не отдаёт пользовательские данные.

До первой реальной операции необходимо:

1. проверять SID пользователя клиента;
2. проверять Session ID;
3. привязывать запрос к разрешённой интерактивной сессии;
4. fail closed при любой ошибке идентификации;
5. добавить межпользовательские Windows integration tests;
6. на стороне GUI проверять PID/token/SID настоящей `NetPilot.Service`, чтобы локальный процесс не мог подменить сервер Named Pipe;
7. учесть PID reuse/TOCTOU и по возможности использовать данные непосредственно из pipe/token impersonation APIs.

Отслеживается issue #6.

### 2. Пользовательские health-check URL

`ResourceDefinition` уже содержит `Uri`, но сетевой health-check ещё отсутствует. До его реализации обязательны защита от SSRF/DNS rebinding, запрет loopback/link-local/private сетей, повторная проверка redirect и запрет передачи cookies/system credentials.

Отслеживается issue #7.

### 3. Реальная цепочка обновлений

До загрузки релизов нужны точный allowlist, HTTPS, контроль redirect, digest/signature policy, staging, безопасная распаковка, rollback, downgrade protection и запрет долгоживущих GitHub-токенов в приложении.

Отслеживается issue #8.

### 4. Резервные копии

После аудита принято более строгое разделение:

- `%LocalAppData%\NetPilot\Backups` — пользовательские копии, доступные только соответствующему пользователю;
- `%ProgramData%\NetPilot\SystemBackups` — только системный rollback без пользовательских секретов;
- переносимый экспорт — место выбирает пользователь.

Секреты не экспортируются по умолчанию. Экспорт с секретами — только после явного выбора и с аутентифицированным шифрованием.

Отслеживается issue #9.

### 5. Windows Service / installer hardening

До первого установщика необходимы защищённые ACL Program Files/ProgramData, безопасный service path, решение по минимальным правам сервисного аккаунта, защита от DLL/path/reparse-point hijacking и запрет user-writable engine directories.

Отслеживается issue #10.

### 6. Защита `main`

В репозитории нет GitHub Rulesets. Текущий GitHub connector не позволяет изменить branch protection. До первого публичного бинарного релиза необходимо сделать CI и CodeQL required checks и запретить опасные прямые изменения `main`.

Отслеживается issue #5.

## ChatGPT / OpenAI

На текущем этапе NetPilot **не имеет программной связи с аккаунтом ChatGPT или OpenAI**.

Сам факт разработки NetPilot через ChatGPT не передаёт приложению доступ, предоставленный инструментам ChatGPT. Подключение ChatGPT к GitHub существует в среде разработки и не включается в исходный код, сборку, установщик или бинарные файлы NetPilot.

Постоянная политика проекта запрещает без отдельной явно утверждённой интеграции:

- cookie ChatGPT/OpenAI;
- сессионные токены браузера;
- OpenAI API keys;
- автоматическое чтение `OPENAI_API_KEY`;
- данные приложения ChatGPT;
- данные других приложений/аккаунтов;
- автоматическую отправку логов/конфигурации в OpenAI.

Любая потенциальная интеграция с OpenAI в будущем должна быть отдельным опциональным модулем, выключенным по умолчанию, с отдельной моделью угроз и отдельным явным решением владельца проекта. Скрытая зависимость NetPilot Core от OpenAI запрещена.

## Автоматические проверки

Security Foundation R1 уже проходил полную сборку, тесты и CodeQL. Для текущего hardening-PR повторно запускаются:

- security-policy check;
- NuGet Audit;
- полная сборка solution;
- автоматические тесты;
- CodeQL.

Важно: успешное завершение CodeQL workflow означает успешное выполнение анализа, но текущий подключённый GitHub-инструмент не предоставляет отдельный API списка Code Scanning alerts. Перед релизом вкладка GitHub Security должна проверяться отдельно.
