# Аудит безопасности NetPilot — 28.10.2026

## Область проверки

Проверен текущий код NetPilot после Security Foundation R1: проекты приложения, Core, IPC, Windows-службы, Windows-платформенного слоя, безопасности, резервного копирования, обновления, абстракций движков, тестов и центрального списка зависимостей.

Дополнительно выполнен целевой поиск по репозиторию на признаки:

- OpenAI / ChatGPT;
- API-ключей, токенов и паролей;
- HTTP-клиентов и сетевой отправки данных;
- чтения переменных окружения;
- запуска внешних процессов;
- доступа к Windows Registry;
- произвольного чтения файлов;
- скрытых средств доступа к учётным данным.

Проверка относится только к текущему состоянию исходного кода. Она не является математической гарантией отсутствия всех возможных уязвимостей и должна повторяться перед каждым релизом и после добавления сетевых движков, обновлений, импорта, резервных копий или новых привилегированных операций.

## Найденные проблемы и исправления

### 1. Политика привилегированных операций была default-allow

**Уровень:** потенциально высокий для будущих версий, неэксплуатируемый в R1 из-за отсутствия реальных обработчиков.

`OperationPolicy` считал все значения перечисления `PrivilegedOperation` разрешёнными. Если бы позднее появился обработчик и разработчик забыл добавить отдельное ограничение, новая операция могла бы стать доступной автоматически.

**Исправление:** политика переведена на `default deny`. Сейчас запрещены все привилегированные операции. Каждая будущая операция должна включаться отдельно после аудита.

### 2. Подключившийся локальный клиент мог бесконечно удерживать IPC

**Уровень:** средний, локальный отказ в обслуживании.

После подключения к Named Pipe служба ожидала данные без собственного тайм-аута. Локальный аутентифицированный пользователь мог подключиться и не отправлять запрос, блокируя текущий последовательный обработчик.

**Исправление:** введён общий лимит времени IPC-запроса. Клиент и служба прекращают зависший запрос.

## Открытые блокирующие требования

Ни один из следующих пунктов не должен быть обойдён при дальнейшем развитии.

### Межпользовательская изоляция Windows

Текущий ACL Named Pipe разрешает подключение локальным `Authenticated Users`, а R1 проверяет только наличие локально идентифицируемого пользователя. Это допустимо только потому, что служба не выполняет реальные привилегированные действия и не отдаёт пользовательские данные.

**До включения первой реальной операции обязательно:**

1. получить PID процесса-клиента Named Pipe;
2. получить Windows access token процесса;
3. определить SID пользователя;
4. определить Session ID;
5. проверить, что запрос относится к разрешённой интерактивной сессии;
6. добавить тесты, подтверждающие отказ другому локальному пользователю.

Это является release/security gate, а не необязательной доработкой.

### Пользовательские health-check URL

`ResourceDefinition` уже содержит список `Uri`, но сетевой код health-check пока отсутствует. Перед его реализацией необходим валидатор, который по умолчанию запрещает обращения к:

- loopback;
- link-local;
- RFC1918/private сетям;
- локальным административным интерфейсам;
- `file:`, `ftp:` и другим неподдерживаемым схемам;
- адресам, которые после DNS-разрешения меняются на запрещённую локальную сеть.

Необходима отдельная защита от SSRF и DNS rebinding.

### Обновления

Текущий модуль обновления содержит только определения доверенных upstream-репозиториев и ещё не скачивает файлы.

Перед реализацией загрузки обязательны:

- точный allowlist источников;
- HTTPS;
- запрет произвольной смены upstream через импортированную конфигурацию;
- проверка хэша;
- ограничение редиректов;
- защита распаковки от Zip Slip, ссылок и выхода за целевой каталог;
- staging и rollback;
- защита от downgrade, когда она станет применима.

### Резервные копии

Реальная запись backup-файлов ещё не реализована. До реализации необходимо разнести пользовательские и системные данные:

- `%LocalAppData%\NetPilot\Backups` — пользовательские настройки и профили;
- `%ProgramData%\NetPilot\SystemBackups` — системный rollback без пользовательских секретов.

Переносимые резервные копии с секретами допускаются только при явном выборе пользователя и с аутентифицированным шифрованием.

## ChatGPT / OpenAI

На текущем этапе NetPilot не имеет программной связи с аккаунтом ChatGPT или OpenAI.

Сам факт разработки NetPilot через ChatGPT не передаёт приложению доступ, который был предоставлен ChatGPT-инструментам разработчика. Подключение ChatGPT к GitHub существует на стороне среды разработки и не включается в исходный код или бинарные файлы NetPilot.

В проекте закреплён отдельный постоянный запрет на автоматическое чтение:

- cookie ChatGPT/OpenAI;
- токенов браузера;
- OpenAI API key;
- `OPENAI_API_KEY` из окружения;
- данных приложения ChatGPT;
- данных других приложений и аккаунтов.

Любая потенциальная интеграция с OpenAI в будущем должна рассматриваться как отдельная функция, выключенная по умолчанию, и не может появиться как скрытая зависимость NetPilot Core.
