# R42.12.3 — проверка ByeDPI на реальном ПК до публикации

Этот пакет предназначен только для ручной проверки точного reviewed ByeDPI draft на реальном Windows x64 ПК.

Он **не является релизом NetPilot**, не публикует ByeDPI и не включает ByeDPI в production admission.

## Что проверяется

1. Установщик NetPilot ставится штатно и запускает `NetPilot.Service`.
2. Тестовый раннер проверяет точный SHA-256 `ciadpi.exe`.
3. Кандидат временно размещается в защищённом каталоге `Program Files`.
4. Запускается ранее проверенный R34 lifecycle/SOCKS5/HTTP harness:
   - два запуска;
   - два SOCKS5 → HTTP round-trip;
   - корректная остановка;
   - crash reconcile;
   - отсутствие остаточного процесса.
5. Выполняется внешний HTTPS-запрос через локальный SOCKS5 ByeDPI без изменения системного proxy.
6. Проверяется, что состояние системного proxy и WinDivert после теста не изменилось.
7. NetPilot создаёт локальный diagnostic support bundle, пока exact-кандидат ещё находится в защищённом каталоге; `engine-status.json` должен содержать ожидаемый SHA-256.
8. Тестовый ByeDPI-кандидат удаляется после проверки.

## Перед запуском

Скачайте Actions artifact `netpilot-r42-12-3-prepublish-pc-validation-pack` и полностью распакуйте его в отдельную папку.

Не запускайте EXE прямо из ZIP.

## Порядок проверки

### 1. Установить тестовый NetPilot

Запустите:

`NetPilot-Setup-0.1.0-alpha-r42-12-3-x64.exe`

Установку выполняйте обычным способом.

### 2. Запустить проверку ByeDPI

Запустите от имени администратора:

`NetPilot-ByeDPI-PC-Validation.exe`

По умолчанию внешний HTTPS smoke использует `https://example.com/`. URL в evidence не сохраняется.

Для дополнительной проверки конкретного HTTPS-сайта можно открыть Windows Terminal от имени администратора в папке пакета и выполнить:

```text
.\NetPilot-ByeDPI-PC-Validation.exe --target-url "https://example.com/"
```

Используйте только HTTPS URL с обычным DNS-именем. Локальные адреса и IP-адреса раннер отклоняет.

## Где будет результат

После завершения откройте:

`%LocalAppData%\NetPilot\Support`

Главный файл для передачи разработчику:

`NetPilot-ByeDPI-PC-Validation-YYYYMMDD-HHMMSS-UTC.zip`

Внутри находятся:

- текстовый validation evidence;
- стандартный `NetPilot-Diagnostics-...zip`;
- `package-manifest.json` с идентичностью тестового пакета.

Сам `ciadpi.exe` в support ZIP не копируется.

## Как понять результат

Успешный evidence заканчивается строкой:

`RESULT=R42_12_3_REAL_PC_VALIDATION_PASS_BLOCK`

Слово `BLOCK` означает, что production admission по-прежнему закрыт. Успешный PC-тест не публикует draft автоматически.

Если тест завершился ошибкой, всё равно сохраните созданный `NetPilot-ByeDPI-PC-Validation-...zip` и передайте его разработчику. В нём должны быть тип ошибки, этап проверки, app/service logs и SHA-256 установленного кандидата без содержимого пользовательского трафика.

## Приватность

Проверка не меняет системный proxy и не устанавливает WinDivert.

Внешний HTTP/HTTPS body не сохраняется. В evidence фиксируются только факт успеха, HTTP status, длительность и безопасный тип ошибки. URL внешней проверки не записывается.

Диагностические файлы остаются локальными и никуда не отправляются автоматически.
