# Zapret Engine Integration R1

## Назначение этапа

R1 создаёт безопасный каталог и парсер официальных стратегий `Flowseal/zapret-discord-youtube`.

На этом этапе NetPilot **не запускает `winws.exe`**, не исполняет `.bat` и не выполняет команды из `service.bat`. Цель — преобразовать единственный разрешённый вызов `winws` в структурированную модель, которую позднее можно будет передать Windows-службе без shell.

## Источник стратегий

NetPilot рассматривает как кандидаты только файлы верхнего уровня доверенного каталога движка с именами:

- `general.bat`;
- `general (<идентификатор>).bat`.

Например:

- `general (ALT).bat`;
- `general (ALT11).bat`;
- будущий `general (ALT42).bat`.

Количество и имена ALT не зашиваются в NetPilot. Новая официальная стратегия может появиться после обновления движка без выпуска новой версии NetPilot.

Не принимаются:

- произвольные `.bat`;
- вложенные файлы;
- symlink/reparse-point файлы;
- symlink/reparse-point корень движка;
- пустые и чрезмерно большие файлы.

## Что происходит с BAT

BAT используется только как текстовый источник данных.

Строки вроде:

```text
call service.bat ...
set ...
cd ...
```

не выполняются и не превращаются в команды NetPilot.

Парсер ищет ровно один вызов следующей формы:

```text
start "..." /min "%BIN%winws.exe" --параметр=значение ...
```

Переносы строк Flowseal с символом `^` объединяются внутри парсера как текст.

Если вызов `winws` отсутствует, отличается от разрешённого формата либо встречается более одного раза, стратегия отклоняется.

## Структурированная модель

Аргументы сохраняются не как shell-команда, а как отдельные элементы шаблона.

Разрешённые переменные:

- `%BIN%` → `EngineBin`;
- `%LISTS%` → `Lists`;
- `%GameFilterTCP%` → `GameFilterTcp`;
- `%GameFilterUDP%` → `GameFilterUdp`.

Любая неизвестная `%VARIABLE%` приводит к отказу.

Каждый параметр после `winws.exe` должен быть отдельным аргументом, начинающимся с `--`.

## Защитные ограничения

Парсер отклоняет:

- shell-метасимволы `&`, `|`, `<`, `>`, `;`, обратную кавычку и неожиданный `^` внутри аргументов;
- неизвестные переменные;
- пути `.` и `..` после `%BIN%`/`%LISTS%`;
- абсолютные и drive-пути после доверенного placeholder;
- ссылки аргументов на исполняемые и скриптовые файлы;
- незакрытые кавычки;
- слишком длинные строки/аргументы;
- слишком большое число аргументов;
- несколько запусков `winws`.

Даже прошедшая проверку стратегия в R1 **не запускается**.

## Почему NetPilot не исполняет официальный BAT напрямую

Даже официальный upstream может содержать служебные команды, updater, вызовы других скриптов и логику, которая не должна автоматически получать привилегии NetPilot.Service.

Поэтому архитектурная граница выглядит так:

```text
официальный general*.bat
        |
        | только чтение текста
        v
ZapretStrategyParser
        |
        | структурированные аргументы
        v
ZapretStrategyTemplate
        |
        X  запуск в R1 отсутствует
```

Это сохраняет возможность обновляться вслед за Flowseal, не превращая `.bat` в универсальный канал исполнения команд.

## Тесты R1

Автоматически проверяются:

- многострочная стратегия в формате текущих Flowseal-конфигураций;
- `general.bat`;
- будущие имена ALT без изменения NetPilot;
- неизвестная переменная;
- shell-метасимволы;
- ссылка на исполняемый файл;
- traversal через `..`;
- отсутствие `winws`;
- несколько `winws`;
- постороннее имя BAT;
- обнаружение только стратегий верхнего уровня.

## Следующий этап

Следующий этап должен добавить безопасное разрешение структурированных placeholders в реальные абсолютные пути внутри проверенного каталога движка и формирование `ProcessStartInfo.ArgumentList`.

Прямые `cmd`, PowerShell и строковое `ProcessStartInfo.Arguments` остаются запрещёнными политикой CI.

Перед реальным запуском двигателя отдельно проверяются:

- целостность пакета Flowseal;
- путь и ACL `winws.exe`;
- отсутствие reparse-point на пути;
- принадлежность всех файлов разрешённому корню;
- жизненный цикл процесса и WinDivert;
- отдельный типизированный IPC DTO запуска.
