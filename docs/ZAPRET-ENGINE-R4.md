# Zapret Engine Integration R4

## Назначение

R4 добавляет единственную разрешённую точку фактического запуска процесса Zapret и контролируемый lifecycle runner.

На этом этапе runner **ещё не подключён к `NetPilot.Service` и IPC**, поэтому GUI не может инициировать запуск.

## Единственная точка Process.Start

Фактический вызов Windows запуска процесса находится только в:

```text
src/NetPilot.Engine.Zapret.Windows/SystemZapretProcessLauncher.cs
```

CI сканирует весь `src` и:

- отклоняет `Process.Start` в любом другом файле;
- требует существование audited launcher;
- требует ровно один вызов `Process.Start` в этом файле.

Остальные запреты продолжают действовать:

- shell запрещён;
- `UseShellExecute = true` запрещён;
- строковое `ProcessStartInfo.Arguments` запрещено;
- OpenAI/ChatGPT скрытые интеграции запрещены.

## Lifecycle runner

`ZapretProcessRunner` хранит только объект процесса, который был создан его собственным launcher.

Runner не:

- ищет процессы по имени;
- принимает PID от UI;
- завершает чужие процессы по PID;
- перечисляет произвольные процессы системы.

### Start

- перед запуском используется проверенная фабрика `ProcessStartInfo` из R3;
- если уже работает та же стратегия, Start идемпотентно возвращает текущий статус;
- если работает другая стратегия, новый запуск запрещается до контролируемого Stop;
- если процесс завершился сразу после создания, он не сохраняется как Running.

### Stop

- завершается только сохранённый runner-процесс;
- используется завершение дерева собственного процесса;
- ожидание завершения ограничено по времени;
- после остановки дескриптор освобождается;
- поиск/kill по имени процесса отсутствует.

### Dispose

При завершении самого runner он пытается завершить только собственный активный процесс и не блокирует остановку службы бесконечно.

## Тесты

Windows CI проверяет lifecycle через fake process abstraction, поэтому тесты не запускают реальный `winws.exe`:

- повторный Start той же стратегии;
- запрет параллельного запуска другой стратегии;
- Stop только собственного процесса;
- немедленно завершившийся процесс;
- очистка завершившегося процесса при проверке статуса.

Отдельные тесты R3 продолжают проверять параметры реального `ProcessStartInfo`.

## Следующий security gate

Перед подключением runner к `NetPilot.Service` требуется отдельный типизированный IPC-контракт.

Клиент не должен иметь возможность передавать:

- путь к executable;
- список аргументов winws;
- рабочий каталог;
- PID для остановки;
- произвольную команду.

Служба должна принимать только высокоуровневый идентификатор операции/стратегии и самостоятельно строить стратегию и launch plan из защищённого engine root.
