# Неизменяемые принципы безопасности NetPilot

Этот документ содержит правила, которые считаются обязательными для всех будущих версий NetPilot. Изменение этих правил требует отдельного обсуждения, анализа угроз и явного решения владельца проекта.

## 1. Изоляция пользовательских данных

- NetPilot не должен получать доступ к данным другого пользователя операционной системы.
- Пользовательские настройки, резервные копии, журналы и секреты должны храниться с правами доступа, ограниченными соответствующим пользователем.
- Привилегированная служба не должна возвращать одному пользователю сведения, принадлежащие другому пользователю.
- Перед появлением любых IPC-операций, которые читают или изменяют пользовательские данные либо состояние системы, обязательна проверка SID и идентификатора пользовательской сессии клиента.
- Машинные данные и пользовательские данные должны храниться раздельно.

## 2. Запрет скрытого доступа к учётным данным

NetPilot не должен без отдельной явно включённой интеграции:

- читать профили браузеров;
- читать cookie, session storage, local storage или сохранённые пароли браузеров;
- читать Windows Credential Manager, DPAPI-хранилища других приложений или аналогичные хранилища Linux/Android;
- искать токены, API-ключи или пароли в файлах других приложений;
- читать буфер обмена с целью поиска учётных данных;
- сканировать домашние каталоги пользователя в поисках секретов;
- извлекать авторизационные данные из процессов других приложений.

## 3. ChatGPT и OpenAI

NetPilot Core не связан с учётной записью ChatGPT или OpenAI и не должен получать к ней доступ автоматически.

Запрещено:

- использовать cookie или сессионные токены `chatgpt.com`, `openai.com` или `auth.openai.com`;
- извлекать данные авторизации из браузера или приложения ChatGPT;
- искать или автоматически читать `OPENAI_API_KEY` и другие ключи OpenAI из окружения пользователя;
- встраивать личный или разработческий API-ключ OpenAI в исходный код, установщик, мобильное приложение или бинарные файлы;
- передавать журналы, конфигурацию или пользовательские данные в OpenAI без отдельного явного действия пользователя.

Если когда-либо появится необходимость в интеграции с OpenAI, она должна быть отдельным опциональным модулем, выключенным по умолчанию. Перед реализацией обязательны отдельная модель угроз, анализ используемого официального способа авторизации, минимальные разрешения, понятное отображение пользователю передаваемых данных и возможность полностью отключить и удалить интеграцию.

Инструменты ChatGPT, использованные разработчиком при создании NetPilot, не являются частью NetPilot и не должны переноситься в программу вместе с доступом разработчика к GitHub или каким-либо другим аккаунтам.

## 4. Сетевые обращения

- Никакой скрытой телеметрии.
- Никакой автоматической отправки диагностических данных.
- Каждый класс внешних сетевых обращений должен быть документирован.
- Источники автоматического обновления задаются белым списком точных репозиториев/доменов.
- Пользовательские health-check URL не должны давать возможность обращаться к loopback, link-local, приватным административным адресам или другим локальным ресурсам без отдельного расширенного разрешения.
- Перед реализацией пользовательских health-check обязательна защита от SSRF и DNS rebinding.

## 5. Привилегированная служба

- GUI не работает постоянно с повышенными правами.
- IPC не предоставляет возможности выполнить произвольную команду, shell-строку, PowerShell, cmd или Bash.
- Все привилегированные операции запрещены по умолчанию.
- Каждая операция включается отдельно только после реализации проверки входных данных, авторизации и тестов.
- IPC-запросы имеют ограничение размера и времени обработки.
- Один локальный пользователь не должен иметь возможность выполнять операции от имени другого пользователя.

## 6. Резервные копии

Рекомендуемое разделение хранилищ:

- пользовательские локальные копии: `%LocalAppData%\NetPilot\Backups` — только текущий пользователь;
- системные rollback-копии компонентов: `%ProgramData%\NetPilot\SystemBackups` — только системные компоненты, без пользовательских секретов;
- переносимый экспорт: место выбирает пользователь.

Секреты не входят в переносимый экспорт по умолчанию. Если пользователь явно включает секреты, переносимая копия должна использовать аутентифицированное шифрование и пароль пользователя.

## 7. Журналирование

В журнал разрешено записывать только технические события, необходимые для диагностики: версия, состояние компонента, идентификатор стратегии, безопасный код ошибки и время выполнения.

Запрещено журналировать:

- содержимое трафика;
- cookie;
- пароли;
- токены;
- API-ключи;
- полные чувствительные URL и query-параметры;
- историю посещений;
- содержимое IPC-запросов, если оно потенциально может содержать пользовательские данные.

## 8. Безопасное значение по умолчанию

При неоднозначности NetPilot должен выбирать вариант, который предоставляет меньше прав, меньше сетевого доступа и меньше доступа к данным. Ошибка проверки должна приводить к отказу операции, а не к её разрешению.
