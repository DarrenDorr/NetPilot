# Security Foundation R1

## Назначение

Security Foundation R1 создаёт первую рабочую границу между обычным интерфейсом NetPilot и будущими привилегированными действиями Windows.

На этом этапе сетевые движки не запускаются, не устанавливаются и не изменяют параметры системы. Цель R1 — сначала проверить транспорт и модель разрешений, а уже затем размещать за этой границей реальные операции.

## Схема

```text
NetPilot.App
    |
    | типизированный запрос
    v
Named Pipe: NetPilot.Service.v1
    |
    | проверка версии, размера и схемы
    v
NetPilot.Service
    |
    | OperationPolicy
    v
привилегированные обработчики
    (в R1 отключены)
```

## Реализованные ограничения

- IPC использует локальный Windows Named Pipe.
- Сетевые подключения к каналу запрещаются ACL через `NetworkSid`.
- Доступ к каналу разрешён `LocalSystem`, администраторам и локальным аутентифицированным пользователям.
- Служба требует идентифицируемого локального клиента и отклоняет анонимное подключение.
- Протокол имеет явную версию.
- Каждому запросу назначается `RequestId`; клиент проверяет соответствие ответа запросу.
- Размер одного сообщения ограничен 64 КиБ до выделения памяти под полезную нагрузку.
- Неизвестные поля JSON отклоняются.
- Неизвестные команды и операции отклоняются.
- IPC не предоставляет поля для произвольной shell-команды.
- В журналы не записывается содержимое IPC-сообщений.
- В R1 разрешён только безопасный `Ping`; запросы привилегированных операций возвращают `OperationNotEnabled`.

## Ограничение R1

ACL разрешает подключение локальным аутентифицированным пользователям. Это приемлемо, пока реальные привилегированные обработчики отключены. До включения операций, способных менять систему или запускать движки, будет добавлена более строгая привязка клиента к пользовательской сессии/идентификатору безопасности и тесты межпользовательской изоляции.

## Следующий этап

Перед включением первой реальной операции необходимо:

1. добавить проверку SID/сеанса клиента;
2. определить типизированные DTO отдельно для каждой операции;
3. добавить защиту от повторного воспроизведения запросов там, где это требуется;
4. добавить интеграционные тесты ACL и IPC на Windows;
5. только после этого подключать управление жизненным циклом первого движка.
