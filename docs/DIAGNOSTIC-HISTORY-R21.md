# R21 — безопасная диагностическая история

## Статус

R21 добавляет локальную историю результатов health-check для расширенного режима NetPilot.

Главный принцип: **история не является универсальным логом приложения**. В неё разрешён только заранее определённый минимальный набор полей, который уже сформирован безопасным health-check слоем.

## Что хранится

`ResourceHealthHistoryEntry` содержит только:

- `ResourceId`;
- итоговый `ResourceHealthState`;
- `CheckedAt`;
- `Latency`;
- короткий `DiagnosticCode`.

Контракт закреплён unit-тестом через reflection, чтобы добавление нового поля требовало явного изменения теста и review.

## Чего в истории нет

В schema намеренно отсутствуют:

- URL/URI endpoint;
- IP-адрес;
- DNS-ответы;
- HTTP headers;
- HTTP body;
- cookie;
- токены;
- логины;
- содержимое пользовательского трафика;
- exception message;
- stack trace;
- произвольная строка от внешнего процесса.

История не получает `HttpClient`, socket или доступ к network transport.

## Ограничение объёма

По умолчанию история хранит максимум 50 записей.

Жёсткий верхний предел конструктора — 200 записей.

При переполнении самые старые записи удаляются. Неограниченного накопления данных нет.

GUI показывает только последние 12 записей в обратном порядке.

## Только память процесса

R21 не создаёт файл журнала и не использует реестр, БД, облако или внешний сервис.

История существует только в памяти процесса приложения и очищается при `Dispose`/закрытии GUI.

Это означает, что R21:

- не требует новых прав на файловую систему;
- не создаёт новый источник персональных данных на диске;
- не отправляет диагностику автоматически;
- не добавляет телеметрию.

## Валидация

Перед добавлением записи проверяются:

### ResourceId

Разрешены только ASCII:

- `A-Z`;
- `a-z`;
- `0-9`;
- `-`;
- `_`;
- `.`.

Максимальная длина — 64 символа.

Строки с пробелами, переводами строк, URL/path-like содержимым и иными символами отклоняются.

### DiagnosticCode

Если код присутствует, для него действует тот же ограниченный набор безопасных ASCII-символов и максимум 64 символа.

Это предотвращает превращение diagnostic code в канал для произвольного текста или log injection.

### Состояние

`Unknown` и `Checking` не сохраняются.

История принимает только завершённый результат проверки.

Отрицательная latency отклоняется.

## Отображение в GUI

Раздел «История диагностики» доступен только в расширенном режиме.

Для каждой записи показываются:

- локальное время;
- название сервиса;
- итоговое состояние;
- человекочитаемая категория диагностики;
- latency, если она есть;
- безопасный diagnostic code.

Рядом явно указано, что данные существуют только в памяти и что URL/IP/трафик не сохраняются.

## Что R21 не делает

R21 не:

- экспортирует историю;
- пишет журнал на диск;
- отправляет сведения разработчику;
- отправляет сведения в OpenAI/ChatGPT;
- читает браузерные cookie;
- перехватывает пакеты;
- анализирует пользовательский трафик;
- меняет сеть;
- включает native engine.

## Будущий экспорт

Если позже будет добавлен экспорт диагностики, он должен проектироваться как отдельная security boundary.

Минимальные требования:

1. только явное действие пользователя;
2. preview перед сохранением/отправкой;
3. allowlist полей;
4. отсутствие секретов по умолчанию;
5. отдельные тесты редактирования/redaction;
6. отсутствие автоматической отправки;
7. пользователь сам выбирает файл/назначение;
8. security review до включения функции.

R21 сам по себе не создаёт такой путь.
