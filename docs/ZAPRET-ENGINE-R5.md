# Zapret Engine Integration R5

## Назначение

R5 впервые соединяет безопасный lifecycle runner Zapret с `NetPilot.Service` через типизированный IPC.

Главное ограничение этапа: GUI по-прежнему **не может** передать службе путь к программе, аргументы `winws`, PID процесса, рабочий каталог или shell-команду.

## IPC v2

Протокол повышен до версии 2, а имя Windows Named Pipe изменено на `NetPilot.Service.v2`.

Разрешены только команды:

- `Ping`;
- `ZapretListStrategies`;
- `ZapretGetStatus`;
- `ZapretStartStrategy`;
- `ZapretStop`.

Для запуска клиент передаёт только канонический идентификатор стратегии, например `ALT11`.

Идентификатор:

- не может быть пустым;
- ограничен 64 символами;
- содержит только `A-Z`, `0-9` и `_`;
- не является именем файла или путём;
- повторно сопоставляется службой с безопасно обнаруженным официальным `general*.bat`.

## Защищённый engine root

Служба не принимает путь движка из IPC.

Для установленной Windows-версии используется фиксированный корень:

```text
%ProgramFiles%\NetPilot\Engines\Zapret\current
```

До появления установщика отсутствие этого каталога возвращается как штатное состояние `ZapretNotInstalled`.

Каталог и все связанные файлы дополнительно проходят проверки R1–R4: отсутствие reparse-point, выходов за корень, небезопасных ссылок и исполняемых payload в стратегии.

## Выбор стратегии

`ZapretEngineController`:

1. заново обнаруживает только официальные `general*.bat` верхнего уровня;
2. получает ID из имени файла;
3. ищет ровно одно совпадение;
4. повторно читает BAT как UTF-8 текст;
5. повторно запускает безопасный parser;
6. строит `ZapretLaunchPlan`;
7. передаёт план `ZapretProcessRunner`.

BAT не исполняется.

Если два файла нормализуются к одному ID, запуск запрещается с `DuplicateStrategyId`.

## Game Filter

В R5 пользовательский Game Filter ещё не вынесен в настройки NetPilot.

Используется режим «выключен», совместимый с текущей логикой Flowseal:

```text
GameFilterTCP = 12
GameFilterUDP = 12
```

Позднее режим фильтра будет отдельной типизированной настройкой с allowlist значений, а не произвольной строкой из IPC.

## Минимальные привилегии

`OperationPolicy` по умолчанию по-прежнему запрещает всё.

Windows-служба R5 явно включает только:

- `EngineStart`;
- `EngineStop`.

Остаются запрещены:

- `EngineInstall`;
- `EngineRemove`;
- `EngineRepair`;
- `UpdateApply`;
- `BackupRestore`.

## Межпользовательская изоляция

Системный экземпляр Zapret считается общим ресурсом, но право управления активным экземпляром привязывается к SID пользователя, который его запустил.

Если пользователь A запустил Zapret:

- пользователь B не может сменить стратегию;
- пользователь B не может остановить экземпляр;
- пользователь B не получает ID активной стратегии пользователя A.

SID берётся из уже проверенного Windows-токена Named Pipe и не принимается из JSON.

При остановке процесса ownership очищается. При ошибке запуска ownership также освобождается, если процесс не остался активным.

## Что возвращается клиенту

Служба намеренно не возвращает PID `winws.exe` через IPC.

Обычному UI достаточно:

- `Stopped` / `Running`;
- ID активной стратегии — только владельцу активной пользовательской сессии;
- списка безопасно распознанных официальных стратегий.

Это уменьшает ненужное раскрытие деталей привилегированного процесса.

## Безопасный запуск

Единственная точка реального `Process.Start` остаётся:

```text
src/NetPilot.Engine.Zapret.Windows/SystemZapretProcessLauncher.cs
```

CI продолжает запрещать любые дополнительные `Process.Start`, shell, строковое `ProcessStartInfo.Arguments` и `UseShellExecute = true`.

## Тесты R5

Добавлены проверки:

- IPC принимает только канонический ID стратегии;
- старый универсальный `ExecutePrivilegedOperation` отсутствует;
- allowlist привилегий разрешает только явно перечисленные capabilities;
- первый SID получает ownership;
- второй SID не может забрать ownership;
- безопасное освобождение ownership;
- контроллер запускает стратегию только по обнаруженному ID;
- неизвестный ID не запускает процесс;
- дублирующийся ID блокируется;
- несовместимая официальная стратегия не попадает в список пригодных к запуску;
- Game Filter в R5 подставляется как отключённый, а не приходит из IPC.

## Следующий этап

После прохождения CI/Windows CI/CodeQL следующий этап — управление установленным пакетом движка:

1. безопасная установка Flowseal из точного allowlist upstream;
2. staging;
3. проверка хэша и структуры архива;
4. защита от Zip Slip/reparse-point;
5. атомарное переключение `current`;
6. rollback;
7. только после этого — интерфейс установки/обновления движка.
