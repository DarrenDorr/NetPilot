# R42.12.4 — проверка ByeDPI на физическом ПК без прав администратора

> **Только диагностика до публикации.** `PRODUCTION_ADMISSION=BLOCK`; Draft Release `431054375` (`byedpi-v0.17.3`) не публиковать. Проверка не разрешает интеграцию WinDivert/zapret2, изменение системного прокси, отключение защит Windows или обход ошибок установщика.

## Когда нужен этот тест

В отчёте физического ПК от 2026-11-11 подтверждены точные байты ByeDPI, обычный пользователь, loopback SOCKS5, правильный владелец процесса, прямой HTTPS 200 и отсутствие остаточных изменений. **Основной HTTPS через SOCKS5 не прошёл.** После PR #93 валидатор пишет ограниченную цепочку кодов сетевых исключений и, при провале основной стратегии, **только для диагностики** сравнивает заранее разрешённую альтернативу `byedpi-auto-tlsrec`. Даже успех альтернативы не делает общий тест успешным.

**Нужен новый пакет, собранный из `main` после коммита `01c90707bf15afccff33465043213adfcbd83f49`.** Старый архив не содержит расширенной диагностики.

## 1. Получить точный тестовый пакет

1. В репозитории `DarrenDorr/NetPilot` открыть **Actions** → **R42.12.4 No-Admin ByeDPI Standard-User Validation Pack**.
2. Выбрать **Run workflow**, ветка **main**. Не запускать от feature-ветки.
3. Дождаться завершения. Hosted job **может быть красным**, поскольку GitHub-hosted Windows ранее не смог создать тестовый пользовательский процесс; нельзя считать это PASS.
4. В артефактах конкретного прогона скачать `netpilot-r42-12-4-no-admin-pc-validation-pack`. Артефакт хранится **1 день**. Он появляется только после успешной сборки пакета и повторного подтверждения неизменности черновика релиза.
5. Распаковать архив в отдельный каталог для испытания. Сохранить `package-manifest.json`, установщик и `NetPilot-ByeDPI-NoAdmin-Validation.exe` вместе.

Если пакета нет, установка и тест запрещены — сначала разобрать причины ошибки workflow. Артефакт не является публичным релизом.

## 2. Подготовить окружение

- Использовать Windows 10/11 x64 и **реальную стандартную учётную запись без членства в Administrators**; лучше чистый профиль и испытательный ПК. Не использовать «Запуск от имени администратора».
- Не запускать тест на системе, где уже работают `ciadpi.exe` или зарегистрирована `NetPilot.Service`: валидатор должен отвергнуть такое окружение.
- Защиты Windows (включая Defender и Secure Boot, если применим) оставить включёнными. Не менять сетевые настройки и прокси.
- Если возник запрос UAC, SmartScreen или предупреждение безопасности, **не обходить его ради PASS**: зафиксировать обстоятельства и остановиться.
- Выполнять команды в **обычном** PowerShell, не в административном.

## 3. Проверить файлы пакета перед запуском

Перейти в папку с распакованным пакетом (там, где лежит `package-manifest.json`), затем выполнить:

```powershell
$ErrorActionPreference = 'Stop'
$manifest = Get-Content -LiteralPath '.\package-manifest.json' -Raw | ConvertFrom-Json
if ($manifest.production_admission -cne 'BLOCK' -or
    $manifest.release_published -ne $false -or
    $manifest.draft_release_id -ne 431054375 -or
    $manifest.candidate.sha256 -cne '866e99c3c7690326cc6e365fe02980f06ae2b394c045555674fb95db52b0dbdd') {
    throw 'Unexpected package identity or admission state.'
}
foreach ($entry in @($manifest.installer, $manifest.validator)) {
    if ($entry.name -cne [IO.Path]::GetFileName($entry.name)) { throw 'Invalid package filename.' }
    $item = Get-Item -LiteralPath (Join-Path (Get-Location) $entry.name)
    if ($item.Length -ne [long]$entry.size -or
        (Get-FileHash -LiteralPath $item.FullName -Algorithm SHA256).Hash.ToLowerInvariant() -cne $entry.sha256) {
        throw "Package hash/size mismatch: $($entry.name)"
    }
}
'PACKAGE_MANIFEST_HASH_CHECK=PASS'
```

Пакет не запускать, если проверка завершилась ошибкой. Эта проверка не заменяет внутреннюю проверку самого `ciadpi.exe` валидатором.

## 4. Установка и обязательная проверка

Из той же папки, в том же **неадминистративном** окне PowerShell:

```powershell
$install = Start-Process -FilePath (Join-Path (Get-Location) $manifest.installer.name) `
    -ArgumentList @('/VERYSILENT', '/SUPPRESSMSGBOXES', '/NORESTART', '/SP-') -Wait -PassThru
if ($install.ExitCode -ne 0) { throw "Installer exit code: $($install.ExitCode)" }

$installRoot = Join-Path $env:LOCALAPPDATA 'Programs\NetPilot'
$evidenceDir = Join-Path $env:LOCALAPPDATA 'NetPilot\R42.12.4-Evidence'
& (Join-Path (Get-Location) $manifest.validator.name) `
    --install-root $installRoot --evidence-dir $evidenceDir
$validatorExitCode = $LASTEXITCODE
"VALIDATOR_EXIT_CODE=$validatorExitCode"
Get-ChildItem -LiteralPath $evidenceDir -Filter 'NetPilot-ByeDPI-NoAdmin-Validation-*-UTC.zip' |
    Sort-Object LastWriteTime -Descending |
    Select-Object -First 1 FullName, Length, LastWriteTime
```

**Не превращать код `1` в успех.** При отказе основной стратегии валидатор всё равно вернёт FAIL, даже если диагностическая альтернативная стратегия подключилась.

## 5. Что зафиксировать

В отчёте из папки `$evidenceDir` найти, если тест дошёл до этой стадии:

- `EXTERNAL_DIRECT_SUCCESS`, `EXTERNAL_DIRECT_STATUS`, `EXTERNAL_DIRECT_ERROR_CHAIN`, `EXTERNAL_DIRECT_ELAPSED_MS`;
- `EXTERNAL_BYEDPI_SUCCESS`, `EXTERNAL_BYEDPI_ERROR_CHAIN`, `EXTERNAL_BYEDPI_ELAPSED_MS`;
- `DIAGNOSTIC_ALT_STRATEGY`, `DIAGNOSTIC_ALT_SUCCESS`, `DIAGNOSTIC_ALT_ERROR_CHAIN` или `DIAGNOSTIC_ALT_FAILURE_CHAIN`, `DIAGNOSTIC_ALT_ELAPSED_MS` (только при провале основной);
- `FINAL_RUNTIME_RESIDUE`, `FINAL_SERVICE_BOUNDARY`, признаки неизменности system proxy/WinDivert, `RESULT`.

Передать разработчику объединённый `NetPilot-ByeDPI-NoAdmin-Validation-...-UTC.zip` **приватно**, предварительно просмотрев содержимое: диагностические сведения могут раскрывать характеристики локального окружения. Не прикладывать его в публичный issue. Не отправлять cookie, токены, историю посещений или трафик.

## 6. Критерий дальнейшего решения

1. Если первичный HTTPS снова FAIL, сравнить его сетевые error codes и время с прямым запросом и альтернативой. **Не изменять стратегию наугад и не разрешать release**.
2. Если тест прошёл на физическом ПК, всё равно нужен PASS полного hosted standard-user workflow на актуальном `main`.
3. До выполнения всех пунктов `docs/R42.12.4-NO-ADMIN-BYEDPI.md` сохранять `PRODUCTION_ADMISSION=BLOCK`, Draft Release не публиковать.


## 7. Подтверждённое испытание физического ПК — 2026-11-11

Результат получен из **двух локальных архивов**, предоставленных оператором для анализа (не публикуются в репозитории). Вложенный архив диагностики побайтово совпал с отдельно предоставленным; все пять SHA-256 из `checksums.txt` совпали с фактическими файлами. Для приватности здесь приводятся только безопасные итоговые маркеры и временные показатели.

Новая ветка диагностики `DIAGNOSTIC_ALT_*` не исполнялась, потому что первичная стратегия прошла. Это **не** означает, что предыдущий сбой проксированного HTTPS был исправлен определённой причиной: результат подтверждает успешную работу на момент нового теста в данной среде, а не устойчивую работу для всех сетей и ресурсов.

**Оставшийся блокер:** отдельный hosted workflow run `42946553039` от 2026-11-11 закончил `failure` на шаге `Execute pack under isolated standard Windows user` вследствие `CreateProcessWithTokenW failed` **до выполнения** валидации ByeDPI. Генерация пакета, его точная перепроверка и загрузка артефакта прошли. Требуется отдельное исследование кода ошибки native-launch; не считать hosted прогон пройденным, не ослаблять SID/non-admin/cleanup gates.

До полного hosted PASS (или до отдельно рассмотренной, строго эквивалентной политики подтверждения на надёжной управляемой Windows-среде) **черновик ByeDPI не публиковать и `PRODUCTION_ADMISSION=BLOCK` не менять**.
