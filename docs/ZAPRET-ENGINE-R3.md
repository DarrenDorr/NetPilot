# Zapret Engine Integration R3

## Назначение

R3 добавляет Windows-адаптер, который преобразует проверенный `ZapretLaunchPlan` в `ProcessStartInfo`.

Процесс на этом этапе **не запускается**. `Process.Start` отсутствует.

## Основные ограничения

Фабрика запуска повторно проверяет данные непосредственно перед передачей в Windows API:

- `ExecutablePath` должен быть абсолютным;
- файл должен существовать;
- имя файла должно быть ровно `winws.exe`;
- каталог `winws.exe` должен совпадать с `WorkingDirectory`;
- рабочий каталог и файл не могут быть symlink/reparse-point;
- список аргументов не может быть пустым или чрезмерно большим;
- каждый аргумент должен начинаться с `--`;
- в аргументах запрещены NUL и переводы строк.

## Запуск без shell

Формируется только:

```text
FileName = <полный путь к winws.exe>
WorkingDirectory = <проверенный bin>
UseShellExecute = false
CreateNoWindow = true
ArgumentList = [ отдельные аргументы ]
```

Строковое `ProcessStartInfo.Arguments` не используется.

Это означает, что пробелы внутри абсолютных путей не требуют самостоятельного экранирования NetPilot и не интерпретируются командной оболочкой.

## Defense in depth

R1 уже проверяет синтаксис официальной стратегии.

R2 уже проверяет trusted engine root, payload/list-файлы и строит launch plan.

R3 не считает эти проверки достаточными и повторно проверяет критические свойства пути и аргументов на Windows-границе.

## Тесты Windows

Отдельный Windows CI проверяет:

- `UseShellExecute = false`;
- `CreateNoWindow = true`;
- строковое `Arguments` остаётся пустым;
- аргументы присутствуют только в `ArgumentList`;
- другое имя executable отклоняется;
- несовпадающий рабочий каталог отклоняется;
- управляющие символы отклоняются;
- не-option аргументы отклоняются.

## Следующий этап

Следующий этап сможет добавить контролируемый process runner, однако до его подключения к `NetPilot.Service` необходимо:

1. хранить только собственный `Process`/PID;
2. не искать и не завершать процессы по имени;
3. безопасно обрабатывать повторный Start/Stop;
4. не журналировать полную командную строку;
5. повторно проверить ACL каталога установки;
6. не включать `EngineStart` в `OperationPolicy`, пока типизированный IPC-запрос и его параметры не пройдут отдельный review.
